# MOLIDO WEBSITE ARCHITECTURE

### Purpose

The MOLIDO website is the official public gateway to the MOLIDO digital universe.

It should introduce the project, present THE LAST SIGNAL, connect users to official channels, and progressively become the entry point to the future MOLIDO ecosystem.

### PRIMARY GOALS

The website should:

- Explain MOLIDO clearly
- Introduce THE LAST SIGNAL
- Connect users to Telegram
- Connect users to YouTube
- Present current campaigns
- Present daily signals
- Support multilingual content
- Support mobile users
- Provide a future user account system
- Prepare for the future game
- Prepare for AI features
- Maintain strong security

```text
PHASE 0 WEBSITE
The first website must remain lightweight.
Initial objectives:
Landing Page
     ↓
MOLIDO Introduction
     ↓
THE LAST SIGNAL
     ↓
Latest Content
     ↓
YouTube
     ↓
Telegram
```

No expensive backend is required for the first version.

### 3D EXPERIENCE

The website may use 3D elements to create a futuristic experience.

Possible elements:

- 3D signal
- Digital Earth
- Global network
- Floating particles
- Interactive fragments
- Animated transitions
- Dynamic backgrounds

3D must not compromise performance.

### PERFORMANCE RULE

Mobile performance has priority over visual complexity.

The system should:

- Lazy-load heavy assets
- Compress images
- Optimize video
- Minimize JavaScript
- Use caching
- Avoid unnecessary 3D rendering
- Provide fallback visuals for low-end devices

### MOBILE FIRST

The website must be designed for smartphones first.

Required:

- Responsive layout
- Touch-friendly controls
- Readable text
- Fast loading
- Low-bandwidth awareness
- Accessible navigation

Desktop enhancements can be added later.

### MULTILINGUAL SYSTEM

The website should support localization.

Initial target languages:

- English
- Persian
- Arabic
- Hindi
- Urdu
- Chinese
- Turkish
- Azerbaijani

Language should affect:

- UI
- Story content
- Navigation
- Captions
- Campaign content

### COUNTRY SYSTEM

The future onboarding experience may allow users to select their country.

The selected country may influence:

- Language
- Regional content
- Community
- Local campaign timing
- Local missions

Country information must be handled as user data and protected appropriately.

### USER ACCOUNT

The future platform may support:

- Registration
- Login
- Secure sessions
- Profile
- Preferences
- Progress
- Collection
- Notifications

Initial authentication should remain simple.

Future authentication can support stronger methods such as:

- Email
- Phone verification
- MFA
- Passkeys

Security must take priority over convenience for sensitive operations.

### OFFICIAL CHANNEL CONNECTION

The website should prominently provide official links to:

### Telegram: @Molidoo

YouTube: @molido-v7z

Only official links should be displayed.

### DAILY SIGNAL

A central website feature should eventually be:

### Daily Signal

Each day the website may display:

- New signal
- Story fragment
- Image
- Video
- Mystery
- Mission
- Community challenge

This becomes the daily entry point for returning users.

### CONTENT MANAGEMENT

Future content should be manageable through a secure content-management layer.

Content types:

- Stories
- Videos
- Images
- Announcements
- Missions
- Campaigns
- Localization
- Daily Signals

Content publishing should support drafts and approval.

### AI INTEGRATION

Future AI services may support:

- Content generation
- Story generation
- Translation
- Recommendations
- Search
- Personalization
- Community assistance

AI access must be permission-controlled.

### SECOND BRAIN INTEGRATION

The future Second Brain may provide personalized experiences.

Possible functions:

- Remember user-approved preferences
- Track progress
- Recommend content
- Explain quests
- Assist with discovery

Private memory must never be exposed to other users.

### SECURITY

Website security must include:

- HTTPS
- Secure authentication
- Authorization
- Input validation
- Rate limiting
- Secure headers
- Dependency management
- Secret management
- Monitoring
- Logging
- Backup

Database systems must never be exposed directly to the public internet.

```text
ARCHITECTURE
The website should eventually use a modular architecture:
Frontend
   ↓
API Gateway / Backend
   ↓
Authentication
   ↓
Application Services
   ↓
Database
   ↓
Storage
```

AI services should connect through controlled APIs.

### INITIAL ZERO-COST DEPLOYMENT

The first version should prioritize:

- Free hosting
- Free CDN
- Free DNS where appropriate
- Static content
- Open-source libraries
- Free-tier backend services when necessary

The architecture must avoid unnecessary vendor lock-in.

### FUTURE SCALABILITY

The system should be designed so that it can eventually support:

- Large user populations
- Multiple regions
- Multiple languages
- High traffic
- Media delivery
- Game services
- AI services

Scaling should happen only when actual usage requires it.

### SEO

The public website should support:

- Search-engine-friendly pages
- Metadata
- Open Graph
- Structured content
- Sitemap
- Robots policy
- Fast loading
- Accessible HTML

### ACCESSIBILITY

The website should aim to support:

- Keyboard navigation
- Screen readers
- Sufficient contrast
- Readable typography
- Reduced-motion preferences
- Clear navigation

### ANALYTICS

Analytics should focus on useful metrics.

Possible metrics:

- Visitors
- Returning users
- Content engagement
- Campaign performance
- Referral sources
- Conversion to community

Analytics must respect privacy and applicable laws.
